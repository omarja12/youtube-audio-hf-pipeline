Engineering case study / 2026

Collecting thousands of videos from one machine.

What happens when a data pipeline has to survive rate limits, interrupted sessions, an adversarial dependency, and a Windows laptop that wants to sleep?

The jobFailure modesInterruptionThroughputRuntimeResults

01 / Context

The job was simple.
The constraints were not.

Build a speech dataset from a manifest of several thousand YouTube videos: download the audio, package it in AudioFolder layout, and publish it to the Hugging Face Hub.

  • One Windows laptop.
  • A shared connection that YouTube rate-limits within about an hour.
  • No way to leave the machine running unattended overnight.

Everything in the design follows from those three facts. Reliability is not only an operational concern here; it is a data-quality guarantee.

02 / The failure that lies

“Video unavailable” is not a diagnosis.

YouTube returns the same message for a deleted video and a temporary rate limit. The first version treated it as permanent, quietly removing good videos from the job whenever the connection was throttled.

if any(marker in lowered for marker in BLOCKED_MARKERS):
    return Outcome.BLOCKED  # the IP, not the video
if any(marker in lowered for marker in GONE_MARKERS):
    return Outcome.GONE     # unambiguous and permanent
return Outcome.RETRY       # ambiguity stays recoverable

The classifier checks blocked markers first, accepts only unambiguous video-specific phrases as gone, and retries everything else. A retry costs seconds. A wrong permanent failure can cost data forever.

The classifier is pure logic with focused tests, including test_bare_video_unavailable_is_retry_not_gone. The test names the design decision so a future “cleanup” cannot quietly reintroduce the bug.

03 / Interruption is a feature

Stopping must be cheap.

The run only operated in daytime sessions, and interruptions were inevitable. The goal was never to prevent every stop. It was to make every stop safe.

RESET → DOWNLOAD → PACKAGE → UPLOAD → COMMIT → RECORD → DELETE LOCAL

A video enters the running metadata.csv only after its Hub commit succeeds. That ordering gives every crash a safe outcome:

Killed duringNext run
DownloadPartial local files are discarded; the group is redone.
UploadNo commit means nothing is recorded; the group is redone.
After commitThe group is recorded and skipped next time.

There is no state in which a video is recorded but absent. Uploaded-but-unrecorded is merely wasteful and recoverable; recorded-but-missing would be a data integrity failure.

04 / The tuning trap

Faster settings produced less data.

Parallelism looked like the obvious lever. It was also a trap: exceeding what the remote service tolerates creates fake failures before it creates useful throughput.

Workers / delayObserved
8 / 0.5sFast for ten minutes, then good videos began reporting unavailable.
6 / 1sSame failure pattern, only slower to arrive.
4 / 3sSustained for hours.

The remote service sets the real throughput ceiling. Good pipeline settings are measured against data quality, not only the number on a progress bar.

05 / Dependencies and the machine

The environment is part of the system.

Cookies and JavaScript

Anonymous bulk access is blocked quickly. On current Windows, browser cookie encryption also makes the obvious browser-import path unreliable. The working configuration uses an exported Netscape cookie file and Deno for YouTube’s JavaScript challenge.

def child_env(config):
    env = os.environ.copy()
    if config.js_runtime_bin and config.js_runtime_bin.exists():
        env["PATH"] = str(config.js_runtime_bin) + os.pathsep + env.get("PATH", "")
    return env

The runtime is injected into the downloader subprocess, keeping the parent environment untouched and making the dependency visible at the boundary.

Keeping Windows awake

A network-heavy process looks idle to Windows. The pipeline declares its power requirement for the duration of the run and releases it on exit, rather than mutating the user’s global power plan.

The guard does not override a closed laptop lid. The documentation says so plainly: honest limits are part of a reliable tool.
